# homelab-proxmox

Infrastructure-as-code for my Proxmox-based homelab.

- **Terraform** manages Proxmox resources (VMs, LXCs, networks, disks).
- **Ansible** configures the Proxmox host and services inside LXCs.
- **GitHub Actions** runs on a self-hosted runner (Raspberry Pi) to apply changes.
- Services are split into **one LXC per service** (Immich, AdGuard, Home Assistant, reverse proxy).

See:

- `docs/architecture.md` -- overall design
- `docs/network-layout.md` -- planned network segmentation
- `docs/operations/` -- operations manual and topic index
- `docs/runbooks/` -- step-by-step operational procedures

## Prerequisites

- **Terraform** >= 1.5.7
- **Ansible** >= 2.10
- **Proxmox VE** 8.x
- **go-task** (the `task` command)
- A `terraform/environments/prod.tfvars` file (see `terraform/terraform.tfvars.example`) with your Proxmox credentials.
- Proxmox API token for Terraform -- see [API Token Setup](docs/runbooks/proxmox-api-token-setup.md)

Install `task`:

```bash
brew install go-task/tap/go-task
```

## Usage

### GitHub Actions Workflows (Recommended)

This repo includes bounded-input GitHub Actions workflows for safely deploying a single service:

- `.github/workflows/lxc-deploy-lab.yml` — LAB-only plan or plan+apply.
- `.github/workflows/lxc-promote-lab.yml` — LAB-only promote (plan+apply), no PROD steps.
- `.github/workflows/lxc-promote-prod.yml` — PROD promotion pipeline (explicit `ref` checkout → LAB apply → best-effort confidence suite → PROD plan + evidence). If LAB/suite fails, PROD plan still runs.
- `.github/workflows/lxc-apply-prod.yml` — Manual PROD apply (workflow_dispatch) that deploys from the saved plan generated by the promotion run. This is used as the approval gate when GitHub Environment required reviewers are unavailable.

Legacy (to be deprecated):
- `.github/workflows/lxc-promote.yml` — combined LAB → PROD workflow.

Notes:
- For PROD runs, `prod.tfvars` is rendered on the Proxmox host and a redacted proof is included in the evidence pack (secrets are never written to the repo).

Automation runner:
- Python entrypoint (module): `PYTHONPATH=python/src python3 -m homelab_proxmox_orchestrator.cli plan|apply|verify|summary`
- Recommended wrapper (uses repo-local `.venv` via `uv` when available): `bash scripts/lab/python.sh -m homelab_proxmox_orchestrator.cli ...`
- LAB workflow internal toggle: set repository variable `USE_PY_RUNNER=true` to have `.github/workflows/lxc-deploy-lab.yml` invoke the Python runner on PVE via `scripts/lab/python.sh` (workflow_dispatch inputs remain unchanged)

### 1. Provision Infrastructure (Terraform)

```bash
cd terraform
terraform init
terraform validate
terraform plan -var-file=environments/prod.tfvars
# terraform apply -var-file=environments/prod.tfvars
```

### 2. Configure Services (Ansible)

First, generate the inventory from Terraform state:

```bash
task inventory:update
```

Then run the playbooks:

```bash
cd ansible
ansible-playbook playbooks/site.yml
```

**Available playbooks**:

- `site.yml` - Apply all configurations to all hosts (bootstrap + services + host config)
- `bootstrap.yml` - Initial setup of LXC containers (run after Terraform provision)
- `services.yml` - Configure LXC services (Immich, AdGuard, Home Assistant, reverse proxy)
- `host_proxmox.yml` - Configure Proxmox host-specific settings
- `backup_proxmox.yml` - Deploy Proxmox configuration backup system
- `tailscale.yml` - Configure Tailscale subnet router for remote access
- `verify_tailscale.yml` - Verify Tailscale configuration (diagnostics)
- `update_monthly.yml` - Monthly security updates with orchestrated reboots

---

### 3. Monthly Maintenance

Run monthly security updates with automatic reboots:

```bash
cd ansible
ansible-playbook playbooks/update_monthly.yml
```

This orchestrates package updates across all services with serial execution to minimize downtime. See [Monthly Patching Runbook](docs/runbooks/monthly-patching.md) for detailed procedures.

**Optional**: Patch Proxmox host with reboot:
```bash
ansible-playbook playbooks/update_monthly.yml -e "allow_host_reboot=true"
```
