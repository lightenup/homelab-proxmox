# Implementation Plan - Service Health Automation & Drift Detection

**Feature Branch**: `018b-health-auto-drift`
**Status**: Draft

## Phase 1: Python Runner Enhancements

The core runner needs to support notifications and coverage analysis before we automate it.

### 1.1 Notification Logic
- **File**: `scripts/healthcheck/healthcheck.py`
- **Task**: Add `send_email_notification(results, config)` function.
- **Details**:
    - Use `smtplib` (standard lib).
    - Config passed via environment variables (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `SMTP_TO`).
    - **Logic**: Compare current result with previous result (from `artifacts/healthcheck/history/latest.json` if available).
    - **Trigger**: Send email ONLY if state changes from Success -> Failure (or if coverage gaps are found).
    - Construct a simple HTML or Text body summarizing failures.

### 1.2 Coverage/Drift Logic
- **File**: `scripts/healthcheck/healthcheck.py`
- **Task**: Add `--check-coverage` flag (or integrate into main run).
- **Details**:
    - Iterate through the inventory (passed via JSON).
    - Check if hosts in groups defined by `healthcheck_enforced_groups` (default: `['services']`) have `healthcheck_path` defined.
    - **Behavior**: If gaps are found, treat as a failure (add to failure list), return exit code 1.
    - This runs *in addition* to standard checks during the scheduled run.

## Phase 2: Ansible Automation

Deploy the runner as a system service.

### 2.1 Systemd Units
- **File**: `ansible/roles/healthcheck_automation/templates/healthcheck.service.j2`
- **File**: `ansible/roles/healthcheck_automation/templates/healthcheck.timer.j2`
- **Details**:
    - Service runs `scripts/healthcheck/run.sh`.
    - Timer runs on a schedule (default: hourly).
    - Service runs as a dedicated user or existing user (e.g., `ansible` or `root` depending on permissions needed, likely `ansible` user is fine if it has access to the script).

### 2.2 Ansible Role
- **File**: `ansible/roles/healthcheck_automation/tasks/main.yml`
- **Details**:
    - Ensure `scripts/healthcheck/` is synced/present on the controller (or wherever this runs - likely the Ansible controller itself, or a specific monitoring node. *Assumption: This runs on the Ansible Controller/Runner node*).
    - Install systemd units.
    - Enable timer.
    - Populate `secrets.yml` (or similar) with SMTP credentials.

### 2.3 Wrapper Script Updates
- **File**: `scripts/healthcheck/run.sh`
- **Details**:
    - Add logic to rotate logs/history (keep last 7 days or last 50 runs).
    - Ensure environment variables for SMTP are loaded (potentially from a `.env` file generated by Ansible).

## Phase 3: Documentation & Verification
