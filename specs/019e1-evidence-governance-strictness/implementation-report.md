# Implementation Report: Feature 019e1 - Evidence Governance Strictness

**Date**: 2025-12-31
**Status**: Completed
**Feature Branch**: `019e1-evidence-governance-strictness`

## Summary
This feature enforces strict governance on Evidence Packs generated by the `pve-lab` harness. It ensures that all checks emitted by the harness (and Ansible) strictly adhere to the `catalog.json` Source of Truth (SSOT) regarding titles, phases, severity, and ownership. It also introduces a self-verification gate that runs automatically after every suite execution.

## Implemented Capabilities

### 1. Verifier Strictness (`verify_evidence.py`)
The verifier now enforces the following rules:
*   **Title Consistency (CAT-005)**: Emitted titles must match `catalog.json` exactly.
*   **Phase Consistency (CAT-006/007)**: Emitted checks must include a `phase` field that matches the catalog.
*   **Severity Consistency (CAT-008)**: Emitted severity must match the catalog.
*   **Ownership Enforcement (OWN-002/003)**:
    *   Checks owned by `ansible` must have `source: ansible` and reference an assertion report.
    *   Checks owned by `harness` must have `source: harness`.

### 2. Harness Updates (`pve-lab`)
*   **Metadata Injection**: The harness now injects `source` and `phase` into every check record.
*   **Phase Context**: `pve-lab` maps the active profile to a catalog phase (e.g., `bootstrap` -> `bootstrap`, `hypervisor-*` -> `tier2`) and exports `CURRENT_PHASE`.
*   **Ansible Integration**: The `ansible-check-bridge.sh` and assertion ingestion logic now correctly attribute Ansible checks to `source: ansible` and the correct phase.
*   **Auto-Verification**: Every suite run now automatically executes `verify_evidence.py` upon completion. If verification fails, the run is marked as failed (unless `--no-verify` is used).

### 3. Diff Tool Enhancements (`diff_evidence.py`)
*   **Catalog Resolution**: The diff tool now loads `catalog.json` to resolve check titles. This ensures that even if an evidence pack is missing titles (or has malformed ones), the diff report remains human-readable and stable using the SSOT.
*   **Profile Safety**: The diff tool now prevents comparing packs from different profiles.

## Validation & Testing

### Negative Testing (Fixtures)
We created a suite of negative test fixtures in `scripts/lab/fixtures/` to validate the verifier's strictness:
*   `invalid-title-mismatch`: Confirmed rejection (CAT-005).
*   `invalid-phase-missing`: Confirmed rejection (CAT-007).
*   `invalid-owner-mismatch`: Confirmed rejection (OWN-003).
*   `invalid-ansible-no-report`: Confirmed rejection (OWN-004).

### CI Verification
The `scripts/lab/ci-verify.sh` script was updated to run these fixtures, ensuring that the verifier logic cannot regress.

### Manual Verification
We verified that `pve-lab` correctly triggers the verifier and that the diff tool correctly resolves titles from the catalog.
